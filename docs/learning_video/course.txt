@chapter Algebra and functions: the language of layers
@scene Variables, functions and composition
@point A variable names a value; a function transforms values.
@point Composition means using one output as the next input.
@point Order matters: f(g(x)) need not equal g(f(x)).
@math f(x) = 2*x + 1; g(x) = x*x
@say A variable is a name for a quantity. A function is a rule that takes an input and returns an output. If a function doubles a number and adds one, an input of three gives seven. If another function squares its input, three gives nine. Now compose them. Doubling the square and adding one gives nineteen. Squaring the doubled-plus-one result gives forty nine. Same two functions, different order, different answer.
@say Neural networks are compositions. A linear layer is followed by an activation, then another linear layer, and perhaps normalization. You cannot rearrange these freely. In our particle embedding, LayerNorm happens before the first linear projection. Moving it after the activation creates a different computation even if all the dimensions still fit. सही shapes होना जरूरी है, लेकिन सिर्फ shapes सही होने से mathematics सही नहीं हो जाती।
@say We often write a function as if it were one symbol to hide details temporarily. Calling something an embedding does not make it mysterious. It is still a specific sequence of operations with learned numbers. Whenever a box feels magical, expand it into its smaller functions and test those functions on a small example.
@scene Sums, indices and the meaning of a subscript
@point i selects a receiving particle; j selects a neighbour.
@point c selects a feature channel; b selects a jet.
@point A repeated sum index is local to that sum.
@math s_i = sum_j r_ij / N
@say A subscript is an address. If a vector contains three measurements, the first subscript can select which measurement we mean. For particle data, we need more addresses: which jet, which particle, and which feature. The symbol for a tensor is not enough; you must understand its indexing convention. In pair relations there are two particle addresses, because a relationship belongs to a pair rather than to just one particle.
@say Consider the average relation for particle i. Hold i fixed, move j over the possible neighbours, add the relation vectors, and divide by the number of valid neighbours. The summation removes the j axis. It does not remove i, because we need one summary for each receiving particle. If the relation tensor has shape batch by particles by particles by channels, summing over the neighbour axis leaves batch by particles by channels.
@say इसे table की तरह सोचो। One row belongs to one receiving particle. You average across that row, not across the whole table. A surprisingly common bug is to sum over the wrong particle axis. The result can have the expected shape when both axes have the same length, so only a numerical example or a semantic check reveals the mistake.
@scene Powers, square roots, exponentials and logarithms
@point exp and log undo each other on positive values.
@point log compresses large positive dynamic ranges.
@point log(0) is undefined; numerical floors need explanation.
@math log(a*b) = log(a) + log(b), for a,b > 0
@say Exponentiation repeatedly multiplies, while a logarithm asks which exponent produced a positive value. In machine learning, exp usually means the natural exponential and log usually means the natural logarithm. They are inverse functions on their appropriate domains. Logs turn multiplication into addition. They also compress ranges: a quantity growing from one to a thousand changes dramatically, while its logarithm changes much more gently.
@say Particle momenta and angular separations can span wide ranges. The pair features in this repository use logarithms partly to make such ranges more manageable. But a log requires a positive argument. Zero separation or a slightly negative mass squared from rounding cannot simply be passed through log. The code uses small positive floors. That is a numerical convention you must reproduce, not a new physics law.
@say Normalization introduces another distinction. Taking a logarithm, subtracting a fixed shift, multiplying by a fixed scale, and clipping are separate operations. Their order matters. किसी feature का नाम log momentum होने का मतलब यह नहीं कि stored value सिर्फ logarithm है। It may already include shifting and scaling. Always inspect the preprocessing code before interpreting the numeric value physically.
@scene Probability and softmax without mysticism
@point Probabilities are nonnegative and sum to one.
@point Logits are unrestricted scores, not probabilities.
@point Subtract the maximum before exponentiating.
@math softmax(z)_j = exp(z_j - max(z)) / sum_k exp(z_k - max(z))
@visual attention
@say If two classes have logits zero and zero, their probabilities are one half and one half. If the logits are zero and the natural log of three, the exponential weights are one and three, so the probabilities are one quarter and three quarters. Softmax converts relative scores into normalized positive weights. Adding the same constant to every logit changes neither probability, because the common exponential factor cancels.
@say This cancellation gives a useful numerical trick. Subtract the largest logit before exponentiation. The largest exponent then becomes zero, preventing unnecessarily huge intermediate values. The relative probabilities stay the same. This is not changing the model's decision; it is computing the same expression more safely. Mature library functions implement this stability internally.
@say Later, attention uses softmax over candidate keys for each query. The classifier uses softmax over classes for each jet. Same mathematical function, different axis and meaning. हमेशा पूछो: probability किस चीज की है, और किस axis पर sum one होना चाहिए? A probability distribution over neighbours is not the same object as a probability distribution over jet labels.

@chapter Vectors, matrices and tensors
@scene A vector is an ordered list with meaning
@point [energy, charge, angle] is not the same as [angle, energy, charge].
@point Vector addition and scalar scaling act componentwise.
@point A learned channel need not have a simple physical name.
@math [1,2,3] + [4,5,6] = [5,7,9]
@visual tensor
@say A vector is an ordered collection of numbers. The order is part of the representation. If a network expects energy in the first position and charge in the second, swapping those columns gives a different input even if the same numbers are present. Think of the feature order as a contract between your data pipeline and your model. The same contract must hold when training and when evaluating.
@say Vector addition combines corresponding components. Multiplication by a scalar scales every component. Neither operation automatically knows about physical units. Adding energy to an angle would make no physical sense in a raw scientific formula. A learned model can combine normalized measurements numerically, but you still need meaningful preprocessing and a clearly specified convention.
@say After embedding, a particle becomes a vector with many learned channels. These channels are combinations learned for prediction. Channel seven is not guaranteed to mean charge, even if raw feature seven happened to be charge. यही raw feature और latent representation में फर्क है। You may investigate what channels encode, but do not assign physical meanings just because a diagram needs a label.
@scene Dot product versus elementwise multiplication
@point Dot product sums products and produces one score.
@point Elementwise multiplication preserves the vector shape.
@point Gates use elementwise multiplication before a dot product.
@math [1,2] dot [3,4] = 11; [1,2] * [3,4] = [3,8]
@visual gate
@say Take the vectors one, two and three, four. Their dot product multiplies matching entries and adds: three plus eight gives eleven. Elementwise multiplication stops before the addition and returns three, eight. These are different operations with different output shapes. The circled multiplication symbol often used in neural network diagrams denotes the elementwise operation, also called the Hadamard product.
@say In attention, a query vector and a key vector eventually produce one dot product score. In GDS attention, a query is first multiplied elementwise by its query gate, and a key by its key gate. The modified vectors still have the same number of channels. Only then do we multiply matching channels and sum to produce a score. A gate is not itself a dot product.
@say A useful debugging rule follows immediately. If multiplying by your gate removes the channel axis, you probably used a matrix product or a reduction where you needed elementwise multiplication. दूसरी तरफ, अगर attention score में अभी भी channel axis बची है, तो शायद आपने required sum नहीं किया। Shapes reveal the distinction when your notation becomes confusing.
@scene Matrices describe many linear combinations
@point A linear layer combines input channels into output channels.
@point PyTorch stores Linear weights as [out_features, in_features].
@point Bias shifts each output channel.
@math y = x @ W.T + b
@code layer = torch.nn.Linear(3, 2)
@code x = torch.tensor([[1., 2., 3.]])
@code y = layer(x)
@code assert y.shape == (1, 2)
@say A matrix is a rectangular table of numbers. A linear layer uses each row of its weight matrix as one recipe for combining input channels. If the input has three channels and the output has two, there are two recipes, each containing three weights. A bias adds one extra number to each output channel. The total parameter count is six weights plus two biases.
@say Mathematical books often use column vectors and write weight times input. PyTorch commonly represents a collection of examples as rows and stores linear weights with output channels first. Therefore the equivalent row-vector expression is input times transposed weight plus bias. These conventions are compatible once you write the dimensions explicitly. Do not copy a transpose from a formula without checking the convention used by the code.
@say A Linear layer can process a tensor with several leading axes. It transforms the final channel axis and preserves the earlier axes. For an input shaped batch, particles, seventeen, a projection to one hundred twenty eight gives batch, particles, one hundred twenty eight. The same weight matrix is reused for every particle. This is not a different set of learned weights for each position.
@scene Tensors are arrays with named axes
@point F: [B, N, 17] stores particle observations.
@point U: [B, N, N, 4] stores pair observations.
@point Rank counts axes here, not matrix rank.
@math B=2, N=3: F has 102 entries; U has 72 entries
@visual tensor
@say In this course, a tensor means a multidimensional numerical array. A scalar has no axes, a vector has one, a matrix has two, and our pair features have four. People sometimes call the number of axes the tensor's rank. Be careful: matrix rank is a different linear algebra concept measuring independent directions. Context determines which meaning is intended.
@say The batch axis selects a jet. The next axis selects a particle in that jet. The final axis selects one of seventeen features. Pair features need two particle axes: receiving particle and neighbouring particle. With two jets and three padded particle positions per jet, the particle tensor has two times three times seventeen entries. The pair tensor has two times three times three times four.
@say N is often a padded length, not the number of real particles in every jet. A separate boolean mask tells us which positions are real. Two jets can share the same rectangular tensor while having different physical particle counts. Tensor shape alone cannot tell you which rows are padding. यही कारण है कि mask को optional decoration नहीं मानना चाहिए।
@scene Broadcasting, reshape and transpose
@point Broadcasting repeats compatible singleton axes conceptually.
@point Reshape groups entries; transpose exchanges axes.
@point Never reshape to imitate an axis permutation.
@code mask = torch.tensor([[1, 1, 0]],
@code                     dtype=torch.bool)
@code key_keep = mask[:, None, None, :]
@code assert key_keep.shape == (1,1,1,3)
@say Broadcasting allows operations between arrays whose trailing dimensions are compatible: each pair of dimensions must be equal, or one must be one. A singleton dimension can be reused conceptually across many positions without manually building repeated copies. For masking attention, we turn a batch by particles mask into batch by one by one by particles. It then applies the same valid-key rule to every head and every query.
@say Reshape and transpose solve different problems. Reshape changes how a sequence of entries is grouped. Transpose changes which axis is interpreted as which. Multihead attention first splits the channel axis into heads and channels per head, then transposes to place the head axis before the particle axis. Omitting that transpose can create mathematically incorrect products even if a later reshape makes the output dimensions look acceptable.

@chapter Neural networks, gradients and optimization
@scene Why a single straight line is not enough
@point Linear layers alone collapse into one affine map.
@point Nonlinear activations let features interact nonlinearly.
@point An MLP applies shared channel transformations per token.
@math MLP(x) = W2 * GELU(W1*x + b1) + b2
@say A multilayer perceptron, or MLP, is a sequence of learned linear transformations with nonlinear activations between them. Why do we need the nonlinearity? If you compose two affine transformations with no nonlinear operation in between, you can multiply their matrices and combine their biases into a single affine transformation. Stacking them would not create the intended extra expressive structure.
@say An activation changes that. ReLU keeps positive inputs and replaces negative ones with zero. This repository uses GELU, a smooth activation that scales an input according to a Gaussian cumulative distribution function. You do not need to derive the Gaussian integral to use the layer correctly. Understand that it acts independently on each scalar and bends the overall input-output relationship.
@say Inside the transformer, the feed-forward network expands each particle's channel vector, applies an activation, and projects back. It does not directly mix particle positions. Attention performs communication between particles; the MLP transforms the information stored within each particle representation. दोनों useful हैं, लेकिन दोनों का काम अलग है। Calling every operation attention would hide this important division of labour.
@scene Derivatives measure local sensitivity
@point A derivative is a local rate of change.
@point A partial derivative changes one variable at a time.
@point A gradient collects sensitivities to many parameters.
@math f(w)=w*w; df/dw=2*w
@say You may know derivatives from school calculus. The derivative tells us how much a function changes for a small input change near a particular point. For the square function, the derivative at three is six. A tiny increase in the input therefore increases the output by roughly six times that tiny amount. This is a local approximation, not an exact statement for a large jump.
@say A neural network loss depends on many parameters. A partial derivative asks what happens when one parameter changes while the others are held fixed. The gradient collects these partial derivatives into an object with the same shape as the parameter tensor. If a weight matrix has two by three entries, its gradient also has two by three entries.
@say Gradient descent subtracts a small multiple of the gradient. We subtract because the gradient points toward local increase of the loss. The learning rate controls the step size. बहुत बड़ा step loss बढ़ा सकता है, even though the direction was locally sensible. A gradient is information about nearby behaviour, not a promise that an arbitrary update will improve the model.
@scene The chain rule is the engine of backpropagation
@point Track local derivatives through composed functions.
@point Sum contributions when a value feeds multiple paths.
@point Autograd records operations; it does not understand physics.
@math x -> a=2*x -> b=a*a; db/dx = 2*a * 2
@say Suppose an intermediate value doubles the input, and the final output squares that intermediate value. To find the final sensitivity to the original input, multiply the sensitivity of the square to the intermediate by the sensitivity of the intermediate to the input. This is the chain rule. If one intermediate contributes through multiple paths, those contributions add.
@say Backpropagation applies this rule efficiently across the computational graph. PyTorch records the operations involving tensors that require gradients. Calling backward on a scalar loss propagates derivatives into parameter gradient buffers. The framework does not need to know that a feature represents momentum. It only needs differentiable numerical operations and the relevant local derivative rules.
@say There are deliberate exceptions. Labels are discrete targets. An argmax prediction is not a useful differentiable path for training. Therefore we train from logits using a smooth loss rather than taking the winning class first and trying to differentiate that integer. अगर आपने loss से पहले argmax कर दिया, तो सीखने का रास्ता टूट सकता है। Keep hard decisions for reporting predictions, not for the basic training loss.
@scene Cross-entropy turns probabilities into a penalty
@point The loss penalizes low probability on the true class.
@point Feed raw logits to torch cross_entropy.
@point For one example, the logit gradient is p - one_hot(y).
@math loss = -log(p_true)
@code logits = model(features, pairs, mask)
@code loss = torch.nn.functional.cross_entropy(
@code     logits, labels)
@code loss.backward()
@say If the correct class receives probability one half, the negative natural logarithm is about zero point six nine. If it receives probability one tenth, the penalty is about two point three zero. If it receives a probability near one, the penalty approaches zero. Cross-entropy therefore rewards assigning high probability to the correct label, not merely winning by a tiny margin over the wrong labels.
@say PyTorch's cross entropy function expects raw logits for the usual classification use case. It combines a stable log-softmax with the target selection internally. Do not apply softmax first and then pass those probabilities as if they were logits. The label tensor contains integer class indices, and its batch dimension must align with the batch of predictions.
@say The derivative with respect to a logit has a beautiful form: predicted probability minus the one-hot target. For the true class, the gradient is negative unless its probability is already one. For other classes it is positive. Gradient descent therefore tends to raise the true-class logit and lower the others, with all earlier layers learning through the chain rule.
@scene A training step and what zero_grad means
@point Zero old gradients, predict, compute loss, backpropagate, step.
@point Gradients accumulate unless explicitly cleared.
@point train() and eval() change dropout behaviour.
@code optimizer.zero_grad(set_to_none=True)
@code logits = model(f, u, mask)
@code loss = F.cross_entropy(logits, labels)
@code loss.backward()
@code optimizer.step()
@say A standard training step starts by clearing gradient buffers. Next run the model, compute the loss, call backward, and ask the optimizer to update parameters. PyTorch accumulates gradients by default. This is useful for intentional gradient accumulation, but it becomes a bug if you accidentally mix gradients from unrelated optimizer steps. Clearing gradients is not resetting learned weights.
@say AdamW adapts updates using running statistics of gradients and includes decoupled weight decay. You can learn its full derivation later; initially, understand which quantities persist between steps. Optimizer state matters for resuming training. Saving only model weights lets you perform inference, but it does not reproduce the same training continuation as restoring optimizer and scheduler state.
@say Put the model in training mode while training, and evaluation mode for validation. Dropout randomly drops activations during training but is disabled in evaluation. Evaluation mode does not by itself disable gradient recording, so validation commonly also uses no grad or inference mode. ये दो अलग controls हैं: layer behaviour और gradient bookkeeping। Confusing them can waste memory or make your validation randomly fluctuate.

@chapter LayerNorm, embeddings and residual learning
@scene LayerNorm normalizes one token across channels
@point Compute mean and variance over the final channel axis.
@point Normalize, then apply learned gamma and beta per channel.
@point Gamma multiplication is elementwise, not a dot product.
@math LN(x)_c = gamma_c * (x_c - mean) / sqrt(var + eps) + beta_c
@say Layer normalization starts with one token vector. Compute the mean of its channels, subtract that mean from each channel, and divide by the square root of the channel variance plus a small epsilon. Then apply a learned scale gamma and a learned shift beta to each channel. Gamma does not form a dot product with the vector. The output still has the same number of channels.
@say The variance here divides by the number of channels, not by one fewer as in an unbiased sample variance estimate. PyTorch LayerNorm uses this population-style variance for normalization. Epsilon prevents division by zero and affects the exact output variance. Before the learned affine transformation, the variance is the original variance divided by original variance plus epsilon. It is approximately one when the variance is much larger than epsilon, not exactly one in every case.
@say Gamma and beta then remove any guarantee that the final output has zero mean and unit variance. यह normalization और learned affine step को अलग देखने से समझ आता है। LayerNorm is also not a normalization over the whole batch. Different particles and different jets are normalized independently across their own feature channels.
@scene Work a LayerNorm example by hand
@point For [1,3], mean=2 and population variance=1.
@point Ignoring epsilon, normalized values are [-1,1].
@point Gamma=[2,3], beta=[0.5,-0.5] gives [-1.5,2.5].
@math (([1,3] - 2) / sqrt(1)) * [2,3] + [0.5,-0.5]
@say Let's calculate rather than only naming the layer. The vector one, three has mean two. Its centered values are minus one and one. Their squared values are both one, so the population variance is one. Ignoring epsilon only for this hand calculation, the normalized vector stays minus one, one. Now use gamma two, three and beta one half, minus one half. Elementwise scaling gives minus two, three, and shifting gives minus one point five, two point five.
@say Notice the final values do not have zero mean. That is not a failure; the learned affine step is part of the design. In an actual numerical check, include epsilon and compare with a tolerance instead of expecting exact agreement with a rounded hand calculation. Also choose the same datatype for both implementations.
@say What if all input channels are equal? The centered vector is zero, so the normalized vector is zero even though the denominator is nonzero due to epsilon. The output becomes beta. यह edge case अच्छा test है। It checks that your code avoids division by zero and applies the learned shift on the correct axis.
@scene Embedding means learning a useful representation
@point Particle embedding: LN(17) -> Linear -> GELU -> Linear.
@point Pair embedding: Linear(4,64) -> GELU -> Linear(64,64).

@math F:[B,N,17] -> X:[B,N,128]; U:[B,N,N,4] -> R:[B,N,N,64]
@visual tensor
@say Embedding is a general name for representing an object by a vector. Here the object is either a particle or a pair of particles. The particle embedding first normalizes the seventeen input channels, projects to the hidden width, applies GELU, projects again, and applies dropout. With the standard configuration, each particle ends up with one hundred twenty eight channels.
@say The pair embedding is a separate small network. It takes four interaction features and produces sixty four relation channels using linear, GELU, linear. It does not have the same LayerNorm and dropout sequence as the particle embedding. This distinction matters when reconstructing the actual repository rather than drawing a generic transformer.
@say Both networks share their parameters across positions. Every particle uses the same particle embedding function, and every pair uses the same pair embedding function. They can still produce different outputs because their inputs differ. Learning shared rules is useful for variable-sized collections and permutation symmetry. कोई particular particle index अपनी अलग learned identity नहीं रखता। A different row order should not change the jet's classification when all related tensors are permuted consistently.
@scene Residual connections preserve a path through depth
@point A residual block adds an update to its input.
@point Input and update must have matching shapes.
@point Pre-LN normalizes the update branch before attention.
@math x_next = x + attention(LN(x))
@say A residual connection adds a computed update to the existing representation. Instead of asking a subnetwork to construct a completely new vector, we ask it to propose a change. The original representation has a direct path to later layers. In differentiation, the derivative of the identity path contributes an identity term, which can help optimization across deep stacks.
@say This does not mean gradients can never vanish or explode. It means the architecture contains a useful route that does not require every derivative to pass through every nonlinear transformation. Claims about guaranteed perfect training would be too strong. Residual connections are an engineering tool, not a proof that any depth and learning rate will work.
@say Our particle blocks use pre-normalization. Normalize the current particle state before computing attention, add the attention output to the original state, then normalize again before the feed-forward update and add that update. Note that the second normalization sees the state after the attention residual. If you normalize the original input twice instead, you have changed the block.

@chapter The real inputs: seventeen particle features
@scene Four-vectors and coordinates

@say A four-vector stores three momentum components and an energy. This repository uses the order momentum x, momentum y, momentum z, then energy. @say Transverse momentum is the magnitude in the plane perpendicular to the beam direction. It comes from the x and y momentum components. @say The model's particle tensor has seventeen processed features, but pair features are computed from the stored four-vectors. @scene Padding is absence, not a real zero-valued particle

@chapter Pairwise physics: constructing the second stream
@scene A relation belongs to two particles
@point U[b,i,j] describes the pair i,j inside jet b.
@point Pair inputs have four channels, not seventeen.
@point R is computed once, then reused by particle blocks.
@math U:[B,N,N,4] -> PairMLP -> R:[B,N,N,64]
@visual jets
@say A particle can be described individually, but classification also depends on how particles relate to one another. Are they close in angle? How is momentum shared? What is their combined invariant mass? The pair tensor stores a compact set of such descriptors for every pair in a jet. Each position in this tensor contains four input features, not another copy of all seventeen particle features.
@say The pair embedding turns those four values into a learned relation vector. In the standard configuration it has sixty four channels. We call the collection of these vectors the relational stream. The particle stream contains one state per particle. The relation stream contains one state per pair. यही dual stream नाम का मतलब है। It does not mean query versus key, and it does not mean two separate jet classifiers.
@say In this implementation, the relation vectors are computed once during a forward pass and reused across the particle transformer blocks. They are not repeatedly updated by a second stack of relation transformers. Per-layer gating can summarize the same relations differently as particle states change, which is distinct from changing the relation tensor itself.
@scene Rapidity and wrapped angular separation
@point y = 0.5 * log((E+pz)/(E-pz)).
@point Wrap delta phi into a principal interval.
@point Pair distance uses rapidity difference and wrapped delta phi.
@math delta_ij = sqrt((y_i-y_j)^2 + wrapped(phi_i-phi_j)^2)
@say Rapidity combines energy and longitudinal momentum through a logarithmic ratio. The code floors the relevant positive quantities for numerical stability. For highly relativistic particles, rapidity and pseudorapidity can be close, but they are not identical definitions in general. Our reconstruction follows the rapidity calculation used by the pairwise feature function.
@say Azimuth is an angle around a circle. A particle near positive pi and another near negative pi are close, not almost a full circle apart. Therefore we wrap their angle difference into a principal interval before squaring it. Failing to wrap creates an artificial discontinuity at the coordinate boundary, and the model could learn artifacts from that discontinuity.
@say Combine the rapidity difference and wrapped azimuthal difference using a Euclidean magnitude in that two-coordinate plane. This gives the pair separation used here. The result is floored before taking a logarithm. एक useful test है angles को boundary के दोनों तरफ रखना। The computed separation should be small when the physical directions are close, regardless of which side of the coordinate cut they occupy.
@scene Relative transverse momentum and momentum sharing
@point kt = min(pt_i,pt_j) * delta.
@point z = min(pt_i,pt_j) / (pt_i+pt_j).
@point For positive momenta, z is at most one half.
@math pt_i=20, pt_j=5, delta=0.2 -> kt=1, z=0.2
@say Relative transverse momentum combines the smaller transverse momentum with angular separation. In the displayed example, the smaller momentum is five and separation is zero point two, so the product is one in the chosen units. Momentum sharing compares the smaller momentum with the sum. Five divided by twenty five gives zero point two.
@say Why use the smaller momentum? These quantities are symmetric under exchanging the two particles. Swapping the pair should not change these raw relation features. The momentum-sharing value reaches one half when the two momenta are equal, and becomes small when one particle is much softer than the other. The log of that value is therefore nonpositive for physically positive inputs.
@say Symmetric input features do not imply that the final attention matrix is symmetric. Query and key projections are different, query and key gates are different, and each row has its own softmax denominator. यह बहुत important separation है: input relation symmetry और information flow symmetry एक चीज नहीं हैं। We will revisit this when interpreting attention maps and gates.
@scene Invariant mass and why a pair is not the whole parent
@point Add four-vectors before computing mass squared.
@point m2 = (Ei+Ej)^2 - |pi+pj|^2.
@point A constituent pair need not reconstruct the parent mass.
@math U_ij = [log(delta), log(kt), log(z), log(max(m2,eps))]
@say For a pair, first add their energies and momentum components, then form energy squared minus the squared three-momentum magnitude. This gives invariant mass squared in the units used here. Do not add the individual masses and call that the pair mass. The cross terms encode information about how the two four-vectors combine.
@say Small numerical errors or unusual inputs can produce nonpositive values, so the implementation applies a positive floor before the logarithm. The fourth pair feature is log mass squared, not log mass. Confusing those differs by a factor of two for positive mass and changes the expected input distribution of the trained embedding.
@say A pair of arbitrary jet constituents is not generally the full set of decay products of a parent boson. Therefore its invariant mass is not guaranteed to peak at the parent's mass. Physical interpretation needs care about which particles are selected and what information is missing. हम useful features बनाते हैं, लेकिन हर pair को पूरा decay system नहीं मानते। This prevents a tempting but incorrect explanation of why the relation embedding works.
@scene Self-pairs, masking and learned biases

@chapter Attention from a weighted average
@scene Start with weighted averaging, not queries
@point Each output is a weighted mixture of value vectors.
@point Weights are nonnegative and sum to one per query.
@point Attention learns how to choose those weights.
@math output_i = sum_j A_ij * value_j
@visual attention
@say Before discussing queries and keys, imagine that you already know the attention weights. A receiving particle combines information from other particles using a weighted average of value vectors. If two values are two and ten and the weights are one quarter and three quarters, the result is eight. With vector values, do the same weighted sum independently for every channel.
@say The weights are organized into a matrix. Row i contains the distribution used to update receiving particle i. Column j refers to the source whose value is being read. Each row sums to one before attention dropout. This is a communication mechanism: one particle representation can incorporate information from other particles in the same jet.
@say The remaining question is how to choose the weights from the current input. Attention answers by computing compatibility scores and applying softmax. We do not store a fixed learned weight for every possible particle pair. Instead, shared learned projections create input-dependent scores. इसलिए different jets के attention maps अलग हो सकते हैं, even though the model parameters are unchanged during inference.
@scene Queries, keys and values are learned projections
@point Q asks which features are relevant to the receiver.
@point K describes how a source can be matched.
@point V carries the content that is mixed.
@math Q = X Wq.T + bq; K = X Wk.T + bk; V = X Wv.T + bv
@say Query, key, and value are three learned transformations of the token representation. A library analogy can help: a query describes what you seek, keys describe searchable properties, and values hold the information you retrieve. But these are vectors learned through the classification objective, not literal sentences or manually assigned metadata. The analogy should help organize the roles without becoming a physical claim.
@say Query and key vectors determine compatibility through a dot product. Value vectors are combined using the resulting weights. Because the three projections are separate, the features useful for deciding where to read need not be identical to the features useful to transmit. That separation gives attention flexibility beyond averaging the original particle features directly.
@say The projections include biases in this repository. When deriving exact implementation equations, include those biases rather than silently assuming purely linear maps. For broad conceptual diagrams they are sometimes omitted for readability, but a reconstruction must restore them. हमारे लक्ष्य में concept और exact code दोनों हैं, इसलिए हम shortcut notation को implementation detail से अलग रखेंगे।
@scene Why divide the dot product by square root of width?
@point Many channel contributions add into one score.
@point Under simple assumptions, dot-product variance grows with width.
@point Scaling reduces softmax saturation risk; it is not a universal proof.
@math score_ij = (q_i dot k_j) / sqrt(d)
@say Suppose query and key components are approximately independent, centered, and have unit variance. Each product then contributes variance of roughly one, and summing d such contributions gives variance roughly d. The standard deviation grows like the square root of d. Dividing by that square root keeps the rough score scale more stable as the head width changes.
@say These are motivating assumptions, not exact facts about every trained network. Learned channels can be correlated and have different distributions. Still, the scaling is a practical design that helps avoid starting with dot products so large that softmax is nearly one-hot and its gradients are poorly conditioned for learning.
@say Note which width appears in the denominator. It is the number of channels in one attention head, not the full model width and not the number of particles. With model width one hundred twenty eight and eight heads, each head has width sixteen, so the scale divisor is four. यह छोटी dimension choice बहुत common implementation bug है। Always derive the number from the tensor being dotted.

@visual attention
@say Our query is one, zero. The first key is one, zero, and the second is zero, one. Their dot products are one and zero. The head width is two, so divide the first score by square root of two. @say Use scalar values two and ten just to keep the arithmetic simple. Multiply two by the first probability and ten by the second, then add. The result is approximately four point six four two. This output is neither the query nor the most highly weighted value alone. It is a mixture. In a real head, each value has several channels and the same row of weights mixes all of those channels.
@say Change only the values and the weights remain the same for this isolated computation. Change a key and the weights can change. Change the query and the whole row can change. यही Q, K, V का functional difference है। In the complete network they all depend on the input, but this controlled thought experiment helps isolate their mathematical roles.
@scene Softmax couples every key in the row
@point Increasing one score changes every normalized weight.
@point More weight is relative, not an isolated absolute quantity.
@point The derivative is A_j * (indicator(j=k) - A_k).
@math d softmax(z)_j / d z_k = A_j * (delta_jk - A_k)
@say Softmax normalization couples the candidates. If one score increases while the others stay fixed, its own probability increases and the others decrease. A key can receive less attention even when its own raw score is unchanged, because another candidate became more competitive. Therefore compare complete rows rather than interpreting an individual logit without context.
@say The derivative captures this coupling. A probability's derivative with respect to its own score is probability times one minus probability. Its derivative with respect to another score is the negative product of the two probabilities. You do not need to memorize the symbols immediately. Understand that changing one score redistributes a fixed total of one across the row.
@say This matters when interpreting gates. A gate changes some score contributions, and softmax then changes the whole distribution. @chapter Multihead attention and masks
@scene Several heads, several learned communication patterns
@point D=128 channels split into H=8 heads of d=16.
@point Heads compute separate attention distributions.
@point Concatenate head outputs, then apply an output projection.
@math [B,N,D] -> [B,H,N,d] -> attention -> [B,N,D]
@visual tensor
@say Multihead attention divides the projected channel space into several groups. Each group computes its own compatibility scores and weighted value mixture. With eight heads, the same receiving particle can use eight different attention distributions. This provides several learned communication patterns rather than forcing every channel to share a single distribution.
@say Do not assume one head must learn angle while another learns charge or mass. Such specialization is possible, but head indices have no guaranteed semantic assignments. These interpretations require measurements on a trained model. The architecture provides capacity for different patterns; it does not prescribe a human-readable job title for each head.
@say After attention, we transpose the head and particle axes back, concatenate the head channels, and apply an output projection. That projection mixes information across heads. It also includes a bias in this implementation. The full attention sublayer therefore contains query, key, value, and output projections. Parameter counting must include all four, not only the first three. हर head अलग full-width model नहीं है; total width को हिस्सों में बांटा जाता है।
@scene The exact head transformation
@point Split only the final channel axis.
@point Put heads before particles for batched matrix products.
@point Reverse both operations before the output projection.
@code b, n, d_model = x.shape
@code h = x.view(b, n, heads, head_dim)
@code h = h.transpose(1, 2)
@code # result: [batch, heads, particles, width]
@say Write the axes before writing the code. A projection starts with batch, particles, model channels. Reshape the last axis into number of heads and channels per head. The result is batch, particles, heads, head width. Transpose the middle two axes to obtain batch, heads, particles, head width. Matrix multiplication over the final two axes can now compute an attention matrix for each batch item and each head.
@say Keys are transposed across their final two axes when forming scores. The result has batch, heads, receiving particles, source particles. Multiplying by the value tensor replaces the source-particle axis with value channels. This is a contracted sum over sources. Reading the axes this way explains the matrix operation instead of treating it as a memorized formula.
@say Divisibility is required: model width must be divisible by the number of heads for this equal-width implementation. A width of one hundred twenty eight with eight heads works. A width of one hundred thirty with eight heads does not. Validate configuration constraints before a long training run, not after loading millions of examples.
@scene Mask conventions differ between PyTorch APIs
@point Model input mask: True means real.
@point SDPA boolean attention mask: True means allowed.
@point MultiheadAttention key_padding_mask: True means ignored.
@math additive mask: valid -> 0; invalid -> -infinity
@visual mask
@say This is one of the most important practical warnings in the course. The same boolean value does not mean the same thing in every attention API. Our model input mask uses true for a real particle. PyTorch scaled dot product attention uses true for an allowed position in its boolean attention mask. But MultiheadAttention's key padding mask uses true for a position that should be ignored.
@say Therefore the class-attention code inverts the keep mask before passing it as a key padding mask. If you forget the inversion, you can discard real particles and attend to padding. This bug may still produce finite outputs, so simply checking that the model runs is not sufficient.
@say Another representation uses an additive floating-point mask. Put zero on allowed entries and negative infinity on disallowed entries before softmax. The disallowed exponentials become zero. When pair bias is present, masking is applied to that floating-point logit tensor. अपने notebook में हर mask के साथ उसका meaning लिखो। A variable called mask is not enough documentation when different functions use opposite conventions.
@scene Mask keys, understand queries, preserve real outputs
@point Real queries must never read padded keys.
@point Padded queries can be computed if later paths ignore them.
@point Padding invariance is a behavioural test.
@visual mask
@say Key masking prevents real particles from reading absent particles. We do not necessarily need to zero every padded query output at every intermediate layer, as long as those padded states never become valid keys and never contribute to the final pooling. This distinction can save unnecessary operations, but it places a responsibility on every downstream path to respect the mask.
@say The relation gate also has a neighbour dimension. Its summary must exclude padded neighbours, even if raw padded pair inputs were already zero. With conditioned summaries, scores for invalid neighbours are set to negative infinity before the neighbour softmax. With shared summaries, relation vectors are multiplied by the validity mask and divided by the valid count.
@say To test the complete behaviour, hold real inputs fixed and replace padding with conspicuously different finite values. The output should remain unchanged within tolerance in evaluation mode. This is stronger than looking at a masked attention matrix in one block. It checks all relevant paths together. अगर result बदलता है, तो कहीं ना कहीं padding से information leak हो रही है।

@point Use B=2, N=5, D=16, H=2.
@point Predict shapes for Q, scores and mixed values.
@point Give the last two positions huge values and mask them.
@practice 120

@chapter Particle Transformer: the additive-bias baseline
@scene Why include pair information in attention?
@point Particle embeddings describe individuals.
@point Pair features describe relationships not explicitly stored in one token.
@point A learned per-head bias adjusts compatibility scores.
@math score_hij = dot(q_hi,k_hj)/sqrt(d) + bias_hij
@visual attention
@say Ordinary self-attention learns relationships indirectly from token representations. Particle Transformer introduces explicit interaction information by adding a learned pair-dependent term to the attention logits. This gives the network direct access to selected physical relations between the receiving and source particles when choosing attention weights.
@say In our local implementation, a linear projection maps each relation vector to one bias value per head. Rearranging axes gives batch, heads, particles, particles. That tensor can be added to the content dot-product scores. The bias is not added to the input particle features or to the value vectors. It changes the softmax distribution through the logits.
@say Positive bias makes a candidate more competitive relative to candidates whose scores stay fixed. Negative bias makes it less competitive. But the resulting probability still depends on the entire row and the content scores. एक bias value अपने आप attention probability नहीं है। Keep the distinction between an additive score adjustment and a normalized weight clear when plotting model internals.
@scene Bias is learned from relations, not a free lookup table
@point Same encoder and projection are reused for every pair.
@point Symmetric raw features constrain the possible pair biases.
@point Softmax and Q/K projections can still produce asymmetric attention.
@math bias_hij = w_h dot R_ij + b_h
@say It is tempting to draw the pair bias as an arbitrary matrix of learned numbers. That would be misleading here. The matrix is generated from the current input relations using shared parameters. There is not a permanent independent learned parameter for every possible particle pair or every position in a jet. Different jets produce different bias matrices through the same function.
@say Our raw pair features are symmetric for a valid pair, and the same pair encoder acts on both directions. Consequently the relation vectors and projected raw bias inherit that symmetry, up to numerical effects. But content scores need not be symmetric because the query and key transformations differ. Even if a score matrix were symmetric, row-wise normalization can produce a nonsymmetric attention matrix.
@say This is a useful reasoning pattern. Trace a property through each operation instead of assuming it survives the entire network. Symmetry of one input is not automatically symmetry of the final output. उसी तरह, positive gate values do not imply positive dot products, because the projected query and key channels can be signed.
@scene The local no-gate model is ParT-style, not exact original ParT
@point Disable gates, retain pair bias for the local baseline.
@point Other embeddings and block choices still belong to this repository.
@point A controlled comparison keeps the rest of the pipeline fixed.
@code cfg = GDSParTConfig(
@code     gate_mode="none",
@code     pair_bias=True,
@code     per_layer_gate=False)
@say If we disable the gates and keep pair bias, our attention formula becomes the familiar additive-bias form. This is a useful local ParT-style baseline. However, that does not make the entire network an exact reproduction of the published Particle Transformer architecture. Embedding details, layer choices, training schedule, preprocessing, and implementation conventions can differ.
@say A fair experiment for the effect of gating should hold the rest of the local pipeline fixed. Use the same data split, training budget, optimizer settings where appropriate, and multiple seeds. Then compare a gate-enabled model with a gate-disabled model trained under those conditions. This isolates the architectural choice more directly than comparing a local result with a number reported in a separate paper.
@say Reproducing a published benchmark is also worthwhile, but it is a different task with more requirements. आपको decide करना होगा कि question क्या है: क्या gates हमारे pipeline में मदद करते हैं, या क्या हमने original paper reproduce किया है? Mixing those questions creates stronger conclusions than the evidence supports.
@scene Hybrid v2 keeps both ways of using physics
@point v2 uses gated Q/K and additive pair bias together.
@point Gate-off removes one path, not all relation information.
@point Gate-only v1-style settings are a different configuration.
@math A = softmax((Q*gQ)(K*gK).T / sqrt(d) + pair_bias + mask)
@visual gate
@say The current v2 design is hybrid. Relations influence query and key channel scaling through gates, and they also generate an additive pairwise bias. Therefore saying that GDS replaces bias with gates is incomplete for this configuration. It adds a multiplicative mechanism while retaining the additive mechanism.
@say Turning off gates in this hybrid does not remove all pair information. Pair bias remains unless you explicitly disable it too. Likewise, turning off pair bias while leaving gates tests a different question. An ablation table should state exactly which paths were enabled, along with whether gates were shared or per-layer and which pooling method was used.
@say Older settings use sigmoid gates, shared uniform summaries, no pair bias, and masked mean pooling. The code supports these choices, but they should not be mixed into one vague architecture description. Configuration is part of the model definition. जब किसी checkpoint को explain कर रहे हो, उसके saved settings देखो, सिर्फ constructor defaults नहीं। The reported shared-gate checkpoint is not the same configuration as every default v2 instance.

@point Design four runs: no physics, bias only, gates only, hybrid.
@point Keep data and training budget fixed.
@point State which comparison answers whether gates add value.
@practice 90

@answer Comparing hybrid against bias only most directly asks whether gates add value on top of the local additive-bias architecture. Comparing gates only against ordinary attention asks whether the gate path helps without bias. The full matrix can reveal interactions between the mechanisms. Multiple training seeds and uncertainty estimates are still needed, especially for small differences. @chapter Gating: the defining GDS mechanism
@scene Summarize relations before producing a particle gate
@point A relation vector exists for every i,j pair.
@point A shared gate averages valid neighbours for each i.
@point The summary has one vector per particle, not per pair.
@math s_i = sum_j mask_j * R_ij / sum_j mask_j
@visual tensor
@say The relation stream has two particle axes, but query and key gates need one vector per particle. We therefore aggregate over neighbours. In the shared-gate variant, hold the receiving particle fixed, multiply relation vectors by the valid-neighbour mask, add over neighbours, and divide by the number of valid particles. The result is a relation summary for each particle.
@say This summary is not the same as averaging the particle states. It averages embedded pair features. A particle in a different relational environment can receive a different summary even if one of its individual raw features matches another particle's. The gate can therefore depend on how the particle sits within the jet's pairwise structure.
@say The shared gate is computed once and reused across particle blocks. Shared means shared across depth in this context, not identical for every particle or every jet. Different particles have different summaries and therefore can have different gates. यह terminology साफ रखना जरूरी है। One set of learned gate parameters can produce many input-dependent gate vectors.
@scene Separate MLPs produce query and key gates
@point Query gate MLP and key gate MLP have separate parameters.
@point Each maps 64 relation channels to 128 gate channels.
@point The gate acts after projection, before splitting heads.
@math gQ_i = activation(MLPq(s_i)); gK_i = activation(MLPk(s_i))
@visual gate
@say Two separate MLPs transform the relation summary. One produces the query gate and the other the key gate. Each uses an intermediate width equal to the model width and returns one scaling factor per query or key channel. The networks share the same summary input but not their learned weights.
@say The attention code first computes the usual query and key projections, including their biases. It then multiplies those projected vectors elementwise by the corresponding gates. Only after gating are channels split into heads. This is important: gating the input before projection would generally be a different computation, because a learned matrix mixes channels and does not commute with arbitrary channelwise scaling.
@say Values are not directly multiplied by these gates. Their influence still changes indirectly because gated queries and keys change the attention weights used to combine values. Therefore do not say values are unaffected in every sense. सही statement है कि V पर direct multiplicative gate नहीं लगाया गया। Distinguish the direct operation from its downstream effect.
@scene Identity initialization makes the initial gate neutral
@point Identity mode: g = 1 + tanh(z), range approximately (0,2).
@point Last gate-MLP layer starts with zero weights and biases.
@point Initial gates are exactly one, independent of the summary.
@math z=0 -> tanh(z)=0 -> g=1
@say Identity-mode gates use one plus hyperbolic tangent. For finite real logits, the mathematical range is strictly between zero and two, though floating-point saturation can reach limiting values numerically. A factor below one suppresses a channel's magnitude, while a factor above one amplifies it. Because the factor is positive, it does not flip the sign of that individual channel.
@say The final linear layer of each gate MLP is initialized with zero weights and zero bias. Its output logits are therefore zero even though the earlier layer is randomly initialized. Applying one plus tanh gives exactly one. Multiplying query and key by one leaves them unchanged. This starts the network from a neutral gate path rather than randomly distorting attention immediately.
@say Neutral does not mean permanently inactive. The final gate layer can receive gradients and begin moving away from zero. At the exact initialization, gradients into the earlier gate layer through that zero final weight can be zero; after the final layer changes, that path opens. यह training की शुरुआती dynamics है, gate failure का proof नहीं।
@scene Sigmoid gates and identity gates are different choices
@point Sigmoid gates lie between zero and one.
@point Random sigmoid logits do not give exactly 0.5 everywhere.
@point Comparing configurations requires tracking initialization too.
@math sigmoid(z) = 1 / (1 + exp(-z))
@say A sigmoid gate maps a real logit into the interval between zero and one. It can reduce a channel's magnitude relative to an ungated channel, but it cannot directly scale it above one. An identity-mode gate can both suppress and amplify around a neutral factor of one. These choices affect initialization and the space of accessible rescalings.
@say It is common to say a sigmoid starts at one half. That is only exactly true if its input logit is exactly zero. In the sigmoid mode here, the final gate layer is not initialized to all zeros by the identity-specific initialization rule. Random inputs and random weights generally give a distribution of logits and therefore a distribution of gate values.
@say A model can compensate for some average scaling through learned projection weights, but that does not make all initializations and training dynamics equivalent. जब ablation करते हो, केवल activation नाम नहीं बल्कि initialization भी record करो। Otherwise two runs may differ in both architectural expressiveness and the optimization starting point.
@scene Query gating versus key gating
@point Query gate changes how one receiver scores all candidate sources.
@point Key gate changes how one source is scored by many receivers.
@point Each channel contributes q_ic * k_jc * gQ_ic * gK_jc.
@math score_ij = sum_c q_ic*k_jc*gQ_ic*gK_jc / sqrt(d)
@visual gate
@say Fix one receiving particle. Its query vector is compared with all candidate keys. Changing that particle's query gate modifies the channel weighting used across the whole attention row. Now fix one source particle. Its key is compared with many queries. Changing its key gate can affect the corresponding candidate across many rows.
@say This gives a useful row-versus-column intuition, but it is not a guarantee of simple attention increases or decreases. Each channel contribution includes the signed query component, signed key component, and both positive gates. Contributions from different channels can reinforce or cancel. Softmax then couples all candidates within a row.
@say In a single channel, the gate factors across pairs have an outer-product structure: a query-side factor for i times a key-side factor for j. They are not an arbitrary independent learned value for every pair and channel. The overall content score still sums over channels. इसलिए gating और additive pair bias अलग mathematical structures हैं। Neither should be described as a generic free matrix with no constraints.
@scene A larger gate can reduce attention: a counterexample
@point Query=1; two keys are -1 and 0.
@point Original first-key probability is about 0.269.
@point Double the negative key: probability falls to about 0.119.
@math softmax([-1,0]) != softmax([-2,0])
@visual gate
@say Let's remove ambiguity with the smallest possible example. Use a scalar query of one, a first key of minus one, and a second key of zero. With head width one and no pair bias, the logits are minus one and zero. The first attention probability is about zero point two six nine.
@say Now double the gate on the first key. That key becomes minus two, not plus two. The logits become minus two and zero, so the first probability drops to about zero point one one nine. The gate became larger, yet attention to that key decreased. This is why the phrase, larger gate means more attention, is not generally valid.
@say If a positive scalar uniformly rescales a query and there is no varying additive bias, it rescales the whole row of content logits like an inverse temperature. But general channelwise gates are not uniform scalars, and pair bias changes the situation further. एक आसान analogy को universal theorem मत बनाओ। Use the full equation when signs, channel directions, or additive terms matter.
@scene Gate derivative: what signal reaches a scaling factor?
@point A gate is trained through the downstream loss.
@point Local score sensitivity includes the other gate and signed Q/K.
@point tanh saturation can reduce the derivative through gate logits.
@math d score_ij / d gQ_ic = q_ic*k_jc*gK_jc / sqrt(d)
@say Hold the projected query, key, and other gate fixed for a local derivative. The score derivative with respect to a query gate component is the product of the query component, key component, and corresponding key gate, divided by square root of head width. This quantity can be positive, negative, or zero. The direction in which a gate should move is therefore not determined by the gate value alone.
@say The total loss derivative also includes the attention softmax, the value mixing, later layers, and the classification loss. For a query gate shared across comparisons, contributions from all relevant keys accumulate. If the gate parameters are reused across blocks, their parameter gradients accumulate contributions across those uses as well.
@say Finally, the gate logit passes through tanh. Its derivative is one minus tanh squared, which becomes small near saturation. This creates a distinction between the sensitivity to the gate value and the sensitivity to the network parameters producing that gate. Gradient reasoning is a chain, not a single arrow from a physics feature to a class label.
@scene Gate lab: verify neutrality and reject a false intuition
@point Check all identity-initialized gates equal one.
@point Reproduce the negative-key counterexample.
@point Explain why a gate histogram alone cannot prove usefulness.
@practice 150
@say Instantiate an identity-mode relation gate and pass a random relation tensor with a valid mask. Assert that both returned gates are exactly one. Then implement the scalar negative-key example and print the two softmax probabilities. Finally write why observing nontrivial gate values after training does not prove that retraining a gate-free model would perform worse. This combines an initialization check, a mathematical counterexample, and an experimental reasoning check.
@answer Identity initialization should produce all-one gates. The counterexample gives approximately zero point two six nine before scaling and zero point one one nine afterward. Nontrivial trained gates show that the fitted network uses non-neutral scalings, but usefulness relative to another architecture requires a controlled retraining comparison. A model can depend strongly on a component after co-adapting around it even when an alternative model could learn another solution without that component.

@chapter Shared and conditioned gates inside transformer blocks
@scene Per-layer gates can ask different relational questions
@point Each block can own its own gate module.
@point A projected current particle state weights neighbour relations.
@point The relation tensor itself remains fixed within the forward pass.
@math c_i = Wctx*h_i + bctx
@say In the shared variant, the same relation summary and gates are reused at every depth. In the per-layer conditioned variant, each block owns a separate gate module. It first projects the normalized current particle state into relation-channel space. This context vector helps decide which neighbour relations are relevant at that stage of processing.
@say Early particle states contain relatively local embedded information. Later states have already received messages from other particles. It is therefore plausible that different blocks should emphasize different parts of the relational environment. The architecture allows that, but it does not prove that deeper gates will follow a particular human-interpretable progression.
@say The pair relation tensor is still the same tensor computed at the beginning of the forward pass. What changes is the aggregation weighting, conditioned on the evolving particle state, and the gate parameters owned by each block. यही fixed relations और dynamic summaries का फर्क है। Calling the relation stream recurrently updated would describe a different architecture.
@scene Conditioned neighbour softmax
@point Score each relation against the receiving particle context.
@point Mask padded neighbours before softmax.
@point Use the normalized weights to average relation vectors.
@math alpha_ij = softmax_j(R_ij dot c_i / sqrt(Dp)); s_i = sum_j alpha_ij R_ij
@visual attention
@say For each receiving particle, compare its context vector with every relation vector in its row. Their dot product gives a neighbour score, scaled by the square root of relation width. Mask invalid neighbours, apply softmax over the neighbour axis, and take a weighted sum of relation vectors. The result again has one relation-summary vector per receiving particle.
@say This is an attention-like operation inside the gate generator. It is separate from the main particle attention that mixes value vectors. The inner operation chooses which relation descriptors to emphasize. The outer attention chooses how particle value representations communicate. Keeping these two softmax operations distinct helps explain the code and its computational cost.
@say The context comes from the block's normalized particle state, not directly from the raw seventeen features. The exact equations are implemented using tensor contractions, including einsum. Read an einsum expression by matching the named axes: relation has batch, receiver, neighbour, channel; context has batch, receiver, channel; the dot product removes channel and keeps neighbour.
@scene Assemble one pre-LN block in the right order
@point h=LN1(x); use h for Q/K/V and conditioned context.
@point Add gated attention to x.
@point Add FFN(LN2(updated x)).
@math x1 = x + Attn(LN1(x)); x2 = x1 + FFN(LN2(x1))
@code h = block.norm1(x)
@code gq, gk = block.gate(rel, mask, x=h)
@code x = x + block.attn(h, gq, gk, bias)
@code x = x + block.ffn(block.norm2(x))
@say A block begins with the incoming particle states. Normalize them using the first LayerNorm. If the block has its own conditioned gate, use that normalized state as the gate context. Otherwise use the shared gates computed earlier, or no gates for the baseline. The attention module receives the normalized particle states and the selected gates.
@say Add the attention output to the original unnormalized state. Now normalize this updated state using the second LayerNorm, apply the feed-forward network, and add its result. The order of these residual updates is part of the architecture. A compact implementation can hide the distinction between the original state and the intermediate updated state, so name them explicitly when learning.
@say Both residual outputs keep batch, particles, model width. The relation tensor has a different shape and is not added directly to the particle tensor. It influences the update through gates and pair bias. यही दो streams के बीच fusion है। They interact through carefully shaped functions rather than by adding incompatible arrays together.
@scene What is shared across depth, and what is not?
@point Particle attention and FFN weights differ between blocks.
@point Pair embedding and pair-bias projection are shared in this model.
@point Gate sharing depends on per_layer_gate configuration.
@math shared-v2 parameters: 2,074,420; default per-layer v2: 2,488,116
@say Each particle transformer block has its own attention projections, normalizations, and feed-forward network. The pair embedding is computed once, and the per-head pair-bias projection is also shared across blocks. Gate parameters depend on configuration: one shared gate module for the shared variant, or separate conditioned gate modules for the per-layer variant.
@say With the standard dimensions, the shared v2 model has two million seventy four thousand four hundred twenty parameters. The default per-layer v2 configuration has two million four hundred eighty eight thousand one hundred sixteen. These counts describe the current implementation and settings, not all possible models called GDS. Changing depth, width, or pooling changes the count.
@say Parameter count is only one part of cost. The pair activation tensor can be large even when its generating MLP has relatively few weights. Conversely, many feed-forward parameters can be reused across every particle. जब memory estimate बनाओ, parameter memory और activation memory को अलग रखो। We will calculate a concrete pair-tensor size in the training chapter.

@chapter From particles to one jet prediction
@scene Why pooling is necessary
@point Transformer blocks return one vector per particle.
@point The target is one class per jet.
@point Pooling converts a variable-sized set into one fixed-width vector.
@math [B,N,D] -> pooling -> [B,D] -> classifier -> [B,10]
@visual flow
@say After the particle blocks, every particle has a contextual representation. But our target is not a class for every particle; it is a class for the entire jet. We therefore need a pooling operation that gathers the set of particle states into one fixed-width representation per jet.
@say A simple approach is a masked average. A more flexible approach uses a learned class token that reads information from the particle set through attention. This repository supports both. The pooling choice changes the architecture and should be included when comparing results or loading configurations.
@say Pooling should respect particle ordering symmetry. If we permute the particles and consistently permute all related inputs and masks, the final jet prediction should remain the same up to numerical tolerance in evaluation mode. The intermediate particle states are allowed to permute with the particles; that is equivariance. The final jet output should not change; that is invariance. इन दो words में फर्क समझो: same reordering versus no change in final answer.
@scene Masked mean pooling
@point Normalize particle states, then average only valid rows.
@point Divide by real particle count, not padded length.
@point A simple baseline is useful even when CLS pooling is stronger.
@math pooled = sum_i mask_i * LN(x_i) / sum_i mask_i
@say Masked mean pooling multiplies each normalized particle state by its validity flag, sums over particles, and divides by the real particle count. If a batch is padded to one hundred twenty eight positions but a jet has only twenty real particles, the denominator is twenty. Dividing by the padded length would make the output depend on how much padding happened to be present in the batch.
@say Averaging treats all final particle states equally at the pooling step, but those states already contain information mixed by attention. It is therefore too simplistic to say mean pooling ignores relationships. The relationships may already be encoded in each state before the average.
@say The implementation applies the final LayerNorm to particle states before masked mean pooling in this branch. With class-token pooling, the final LayerNorm is applied to the pooled class state instead. These are not automatically interchangeable operations. एक nonlinear normalization और average को मनमाने order में बदलने से model बदल जाता है। Match the actual branch when reconstructing.
@scene A class token is a learned reader
@point Start with one learned CLS vector per jet.
@point Only CLS is updated by each class-attention block.
@point Keys and values include CLS itself plus all particles.
@math query = LN([CLS; X])[:, :1]; keys,values = LN([CLS; X])
@visual attention
@say The class token begins as a learned parameter vector that is expanded across the batch. Each jet gets a copy of the same initial vector, but it reads different particle states and therefore develops a different pooled representation. Expanding the parameter does not create independent learned class-token parameters for every example.
@say In a class-attention block, concatenate the class token with the particle tokens and normalize. Use only the normalized class token as the query. Use the complete normalized concatenation as keys and values. The class token can attend to itself as well as to the particles. Padding is excluded, while the class-token position is always valid.
@say Only the class state is updated by the attention residual and its feed-forward residual. Particle states are not rewritten by these pooling blocks. The v2 configuration uses two such class-attention layers. Importantly, these blocks use ordinary MultiheadAttention rather than the relation-gated attention module. न gates और न pair bias को इन CLS blocks में automatically assume करो।
@scene The classifier returns logits, not labels
@point Final normalization precedes the classifier.
@point Classifier: Linear(128,128) -> GELU -> dropout -> Linear(128,10).
@point Softmax is for probabilities; argmax is for reported labels.
@math logits:[B,10]; probabilities = softmax(logits, dim=-1)
@say After pooling, the model has one vector per jet. A final normalization and classifier MLP transform that vector into ten logits. The logits are real-valued scores. They need not sum to one, and negative values are perfectly valid. Passing these scores to cross entropy is the standard training path.
@say During evaluation, apply softmax if you need class probabilities, or take argmax if you only need the predicted label. Argmax of logits and argmax of their softmax give the same class because softmax preserves ordering. But metrics such as ranking-based AUC need scores or probabilities rather than only the winning label.
@say Probability calibration is another question. A softmax output of ninety percent does not automatically mean that predictions of that confidence are correct ninety percent of the time. Calibration should be assessed empirically on suitable held-out data. Classification accuracy, ranking quality, and calibration measure different properties. इन्हें एक ही score का अलग नाम मत समझो।

@say PyTorch modules need to know which parameters and submodules they own. Assigning a linear layer as an attribute registers it. For a sequence of blocks that you iterate manually, use ModuleList. @chapter Training safely: data, memory and diagnostics
@scene Synthetic data checks plumbing, not physics performance
@point Random labels are useful for code checks, not benchmark claims.
@point A tiny fixed batch can test whether optimization is connected.
@point Real validation must use held-out real data.
@say A synthetic batch is useful because you can control shapes, masks, and edge cases without loading the full dataset. It can verify that the model returns logits, the loss is finite, gradients exist, and parameters update. Random features and random labels do not establish that the architecture learns meaningful jet physics.
@say A tiny fixed-batch overfitting check can test whether optimization is connected end to end. With enough capacity and appropriate settings, the model should often fit a small fixed collection. Failure can reveal broken gradients, incorrect labels, excessive regularization, or a training-loop error. Success still says little about generalization to unseen jets.
@say Keep the objective of each diagnostic explicit. A forward test checks computation. A gradient test checks differentiation. A tiny fit checks optimization plumbing. A held-out evaluation checks predictive behaviour on a distribution. एक test से चारों claims मत करो। This discipline prevents impressive-looking but meaningless synthetic accuracy reports.
@scene Build pairs per batch instead of storing every dense tensor
@point Cache particle features, four-vectors, offsets and labels.
@point Compute dense pair features from the current padded batch.
@point Group similar particle counts to reduce wasted N squared work.
@math pair storage scales as B * N * N * channels
@say Pair tensors grow quadratically with padded particle count. Storing every dense pair tensor for millions of jets would be expensive. The repository caches compact particle arrays and four-vectors in a ragged representation, with offsets marking each jet's particle range. The loader pads the current batch, and pair features are computed from that batch.
@say Ragged means that jets are stored with their actual particle counts rather than each reserving the maximum number of rows. During batching, shorter examples still need padding for rectangular tensor operations. Grouping jets with similar counts can reduce the maximum padded length in each batch and therefore reduce both particle and especially pairwise work.
@say This optimization must not silently alter the label distribution or validation procedure. Training can shuffle while grouping for efficiency; evaluation should remain deterministic and cover the intended examples. Data loading is part of the experiment, not merely a mechanical prelude. अगर loader कुछ classes skip करता है, तो model architecture सही होने पर भी result misleading हो सकता है।

With batch size thirty two, particle length one hundred twenty eight, and relation width sixty four, the relation tensor contains thirty three million five hundred fifty four thousand four hundred thirty two entries. @say Training needs additional activations, gradients, parameters, optimizer state, and temporary workspace. Attention scores and conditioned-gate operations add their own costs. @say Activation checkpointing trades extra recomputation during backward for reduced stored intermediate activations. Mixed precision can reduce some memory and improve speed on suitable hardware, but stability and hardware support matter. पहले tiny configuration पर correctness, फिर memory measurement, फिर scale up। An out-of-memory error is not solved scientifically by changing several architectural settings without recording them.
@scene Learning rate, schedules and numerical precision
@point Start with a stable small experiment.
@point Warmup and decay change optimizer step size over time.
@point Mixed precision needs appropriate scaling and finite-value checks.
@say The learning rate controls update size, while a schedule changes it over training. Warmup starts smaller and increases toward a chosen scale; decay later reduces it. These choices can strongly affect the comparison between architectures. A gate-enabled model and a baseline should not be compared after accidentally using different effective training budgets or inconsistent schedules.
@say Mixed precision uses lower precision for suitable operations while retaining higher precision where needed. On supported GPUs, autocast and gradient scaling help manage performance and numerical range. The exact API and dtype depend on hardware and PyTorch version. Do not copy a CUDA-only training recipe into a CPU environment and assume the same behaviour.
@say Monitor finite loss values, gradient norms where useful, learning rate, throughput, and validation metrics. If loss becomes nonfinite, surface the problem instead of silently replacing it with zero and continuing. Such a fallback can hide a broken run behind a completed progress bar. Training logs should help diagnose reality, not merely make the run look successful.
@scene Saving, resuming and choosing the checkpoint
@point Save model, optimizer, scheduler, epoch and relevant scaler state.

@say A useful training checkpoint contains more than model weights. To continue the same optimization process, save optimizer state, scheduler state, epoch or step counters, and mixed-precision scaler state when relevant. @say Choose the best checkpoint using validation criteria defined for the experiment. Then evaluate it on the held-out test set. Repeatedly choosing among models based on test accuracy turns the test set into a selection set. यह scientific workflow की बात है, सिर्फ coding style की नहीं। A disciplined selection protocol is as important as a sophisticated attention mechanism.

@chapter Evidence, interpretation and your final project
@scene Accuracy, confusion matrices and AUC answer different questions
@point Accuracy measures the fraction of correct top-class predictions.
@point A confusion matrix exposes class-specific mistakes.
@point AUC measures ranking under a specified multiclass convention.
@math accuracy = number_correct / number_examples
@say Accuracy is easy to understand: count correct predicted labels and divide by the number of examples. But a single average can hide large differences between classes. A confusion matrix shows which true classes are mistaken for which predicted classes. Always label its axes and state whether entries are counts or normalized proportions.
@say AUC summarizes ranking quality rather than only the winning label at one decision rule. In a multiclass task, the aggregation convention matters: one-versus-one and one-versus-rest are not interchangeable names. Macro averaging weights class-level quantities equally, while other averaging schemes use different weights. Compare like with like.
@say The saved ten-epoch shared-v2 result reports about eighty four point eight four percent accuracy and a macro one-versus-one AUC around zero point nine eight five three on the stated test setup. These are measured results for that run, not a promise for every reconstruction or every dataset. वर्तमान remote training status इस video में assume नहीं किया गया है। A historical metric should never be narrated as proof that an unverified current job finished.
@scene Does gating help? Separate three different claims
@point Non-neutral gates show learned scaling.
@point Test-time knockout measures fitted-model reliance.
@point Retrained ablations measure comparative architecture performance.
@visual gate
@say There are three different questions. First, did the trained gates move away from their neutral values? Gate distributions can answer that. Second, does this fitted network rely on its gates? A test-time intervention that replaces them with ones can provide evidence. Third, does including gates lead to better models than training without them? That requires controlled retraining comparisons.
@say These questions are related but not equivalent. If a network co-adapts its projections and downstream layers around a gate, removing that gate afterward can seriously damage performance. A separately trained gate-free network may nevertheless learn a different effective solution. Therefore a large knockout drop does not directly quantify the accuracy gain caused by adding gates to the architecture.
@say Conversely, a small difference between retrained models cannot simply be declared noise without uncertainty analysis. Multiple seeds, dataset sampling, and statistical comparisons matter. हमें neither hype करना है nor बिना evidence dismiss करना है। The correct conclusion should be no stronger than the experiment actually supports.

@scene Gate correlations are hypotheses, not explanations by themselves
@point Correlation with jet radius or momentum can be confounded.
@point Mean gates discard channel signs and Q/K/value interactions.
@point Inspect interventions, attention and outputs before causal stories.
@say Suppose the average query gate correlates with distance from the jet axis. That is an observation about a summary statistic. It does not prove that central particles search for peripheral particles, because attention depends on signed query and key components, both gates, pair bias, and softmax competition. Averaging gate channels discards much of that information.
@say Particle categories, momenta, multiplicities, and angular structure can be correlated with each other. A gate's apparent relationship with one variable may be explained partly by another. This is especially important when the shared gate does not directly receive identity or displacement features. Its correlations with those quantities may be indirect.
@say Better interpretation combines controlled interventions, conditional analyses, actual attention distributions, value contributions, and changes in output predictions. Even attention weights alone are not a complete explanation of a nonlinear classifier. एक attractive physics story बनाने से पहले competing explanations test करो। Scientific restraint is a strength of the project, not a weakness.
@scene Where MoE fits, and what it does not change
@point The extension replaces particle FFNs with routed experts.
@point Shared attention, gates and pooling are distinct from routing.
@point Equal experts can reproduce a dense FFN under exact conditions.
@math output_i = sum_e selected_weight_ie * expert_e(x_i)
@say The related mixture-of-experts project changes the feed-forward part of particle blocks. A router chooses a small subset of expert MLPs for each particle and combines their outputs with weights. This is separate from the query and key gating mechanism we have studied. Both use the word gate in some machine-learning literature, but they control different objects.
@say If all experts are identical copies of a dense FFN and selected mixture weights sum to one, the deterministic mixture output equals that dense FFN output, provided no extra noise or other behaviour changes are introduced. This motivates sparse upcycling from a dense checkpoint. Dropout, routing details, and training can break exact equality outside those conditions.
@say One subtle issue: if only one expert is selected and its selected weight is renormalized to one, the task loss has no gradient to the router through that mixture weight away from routing boundaries. Auxiliary losses or a different routing formulation may be needed. यह advanced extension है; पहले dense GDS reconstruction मजबूत करो। More parameters and sparse activation do not automatically mean lower batch compute or better accuracy.
